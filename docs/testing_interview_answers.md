# Ответы на вопросы о тестировании

## Вопрос 1: Какой у тебя подход к тестированию?

**Ответ:**
Я использую модульное тестирование для проверки критичной бизнес-логики. В проекте SFMShop я написал тесты для всех критичных функций и классов. Использую pytest для написания тестов, фикстуры для подготовки данных и параметризацию для проверки разных случаев. Также применяю TDD для новых функций - сначала пишу тесты, затем реализую код. Для изоляции тестов от внешних зависимостей использую моки через unittest.mock.

## Вопрос 2: Какие типы тестов ты пишешь?

**Ответ:**
Я пишу unit-тесты для проверки отдельных функций и классов. Например, в проекте SFMShop я написал тесты для функций расчета скидок и доставки. Также пишу integration-тесты для проверки взаимодействия между компонентами, например, тесты API endpoints с мокированием внешних сервисов.

## Вопрос 3: Какое покрытие кода тестами?

**Ответ:**
В проекте SFMShop я достиг покрытия более 80% для критичной бизнес-логики. Использую pytest-cov для проверки покрытия. Важно не гнаться за 100% покрытием, а покрывать тестами критичные части: бизнес-логику, функции расчета, обработку ошибок.

## Вопрос 4: Как ты используешь моки?

**Ответ:**
Я использую моки для изоляции тестов от внешних зависимостей. В проекте SFMShop я замокировал запись заказа в базу через `unittest.mock.patch`, чтобы тесты были быстрыми и не зависели от реальной БД. Так же изолирован кэш на Redis в тестах API.

## Вопрос 5: Что такое TDD?

**Ответ:**
TDD (`Test-Driven Development`) - это подход, при котором тесты пишутся ДО кода. Я использую цикл красный-зеленый-рефакторинг: сначала пишу тест, который падает (красный), затем пишу минимальный код для прохождения теста (зеленый), затем улучшаю код, сохраняя тесты зелеными (рефакторинг). В проекте SFMShop я использовал TDD для функции расчета доставки.
