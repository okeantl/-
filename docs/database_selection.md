## PostgreSQL - основная БД

### Данные:
Пользователи (users), товары (products), заказы (orders), отзывы (reviews).

### Причины выбора:
1. **Структурированные данные** - четкая структура таблиц
2. **ACID транзакции** - нужны для финансовых операций
3. **Связи между данными** - внешние ключи, JOIN запросы
4. **Сложные запросы** - агрегация, группировка, фильтрация
5. **Надежность** - проверенная реляционная БД

**Преимущества:** гарантии целостности данных, сложные запросы с JOIN, транзакции для атомарности, широкая поддержка и документация.

## Redis - кэш и сессии

### Использование:
- Кэш списка товаров
- Кэш отдельных товаров
- Сессии пользователей
- Временные данные

### Причины выбора:
1. **Скорость** - хранение в памяти (O(1))
2. **TTL** - автоматическое истечение данных
3. **Простота** - key-value структура
4. **Временные данные** - кэш и сессии не нужны постоянно

**Преимущества:** очень высокая скорость доступа, автоматическое удаление устаревших данных, простота использования, низкая задержка.

## MongoDB - логи и аналитика

### Использование:
- Логи приложения
- Аналитические данные
- События пользователей

### Причины выбора:
1. **Гибкая структура** - разные типы логов имеют разную структуру
2. **Масштабируемость** - горизонтальное масштабирование
3. **Документная модель** - удобно для JSON-подобных данных
4. **Аналитика** - агрегация для аналитических запросов

**Преимущества:** гибкая схема документов, масштабируемость, удобно для логов, быстрые запросы по документам.

## Компромиссы

### PostgreSQL:
- Медленнее Redis для простых операций
- Вертикальное масштабирование
- Фиксированная схема

### Redis:
- Только в памяти (ограниченный объем)
- Нет сложных запросов
- Персистентность настраиваемая (RDB включён из коробки, AOF - опционально для строгой durability)

### MongoDB:
- Многодокументные транзакции есть (с 4.0), но дороже и менее естественны, чем в реляционных БД
- Сложнее JOIN запросы
- Eventual consistency
