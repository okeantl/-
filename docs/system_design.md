# Системный дизайн проекта SFMShop

## Архитектура

### Компоненты:
1. **Load Balancer (nginx)** - балансировка нагрузки между экземплярами API
2. **API Servers (FastAPI)** - несколько экземпляров приложения (горизонтальное масштабирование)
3. **Redis** - кэширование часто запрашиваемых данных
4. **PostgreSQL** - основная БД с репликацией для чтения
5. **CDN** - кэширование статических ресурсов

### Масштабирование:
- **Горизонтальное масштабирование**: несколько экземпляров API серверов
- **Автоматическое масштабирование**: добавление серверов при росте нагрузки
- **Репликация БД**: master для записи, replicas для чтения

### Кэширование:
- **Redis**: кэширование результатов запросов к БД (TTL 1 час)
- **CDN**: кэширование статических ресурсов
- **Browser Cache**: кэширование на клиенте

### Балансировка нагрузки:
- **Round Robin**: распределение запросов по очереди между серверами
- **Health Checks**: проверка доступности серверов

## Метрики производительности

### Целевые метрики:
- **RPS**: 1000 запросов в секунду
- **Latency**: < 100ms для 95% запросов
- **Availability**: 99.9% (uptime)

### Стратегия масштабирования:
- При RPS > 800 на экземпляр — добавить ещё один экземпляр API
- При latency p95 > 150 мс — проверить попадания в кэш и оптимизировать тяжёлые запросы
- При ошибках > 1% — проверить здоровье серверов и health checks балансировщика

## Компромиссы

### Модель согласованности по типам данных:
- **Каталог товаров** — eventual consistency. Допустима задержка 5 минут (TTL Redis).
- **Корзина пользователя** — strong consistency. Чтение из master, без кэша.
- **Остатки на складе** — eventual при просмотре каталога, strong при оформлении заказа (транзакция в БД).
- **Лента рекомендаций** — eventual. Обновление раз в час через фоновый job.

### TTL кэша и обоснование:
- Каталог товаров — 5 минут. Компромисс: пользователь может увидеть устаревшую цену максимум 5 минут, зато БД разгружена на 95%+.
- Профиль пользователя — 1 минута. Профиль меняется редко, но изменения должны быть видны быстро.
- Статические ресурсы (картинки, CSS) — 30 дней через CDN. Меняются редко, можно кэшировать агрессивно.

### Latency vs Throughput:
- Для SFMShop важнее **latency** — пользователь интерактивно ходит по каталогу, любая задержка > 1 секунды воспринимается как «тормозит».
- Throughput оптимизируется только в фоновых задачах (отправка email, генерация отчётов).
